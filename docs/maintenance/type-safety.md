# バックエンドの型整合性

`v12-mod-maintain` で、依存更新後に報告されていたバックエンド301件のTypeScript診断を解消した。保護した `v12-mod` と本番サーバーは変更していない。

## 型定義の変更

- 実行環境に合わせて `@types/node` を24系へ更新。ioredis 4には対応する実際の宣言パッケージを追加し、Koa 2の宣言を統一した。余分な `@types/koa-views` は本体同梱宣言と重複するため削除した。
- Sharpの公開型、TypeORMのジェネリック制約、タイマーの戻り値、MFMの型述語、Maybeの型ガードを正しく定義した。
- 通知イベントのID配列、HTTPヘッダー、GitHub/Twitter/Discord連携情報を実データに対応する型にした。DBのカラム定義やマイグレーションは変更していない。
- APIの基本プロパティと `anyOf` のプロパティ・必須条件を同時に推論する。入力は `unknown` で受け、既存のAJV検証を通過するとパラメーター型へ絞り込む。ディスク上のアップロード情報と、スキーマがあるAPIの戻り値も定義した。
- ActivityPubのオブジェクト、投稿、通知、コレクション、文字列の日時を区別した。Create/Like/Update/Personの描画から複数の `any` を除き、JSON-LDコンテキストを付けても元の型を保持する。
- 宣言のないライブラリと、公開宣言が実行時のCommonJS形式に合っていないライブラリには、利用するAPIの具体的な宣言を追加した。`redis-lock` の独自promisify、pureimageのグラデーションsetter、summalyの `exports.default` などは実装に合わせている。
- file-typeは完全な同梱宣言へ解決する。既存のNodeモジュール解決方式を維持しながら、exports経由でしか公開されない宣言を参照するためのパスを明記した。

新しい `any`、`@ts-ignore`、`@ts-nocheck`、型アサーションによる診断の隠蔽は追加していない。`as const` は定数のリテラル型・タプル型を保持するために使用する。strict設定や検査対象のincludeを弱めていない。`type FIXME = any` は実際のテキストノード型に置き換えた。

301件のうち120件はDI移行前の到達不能な連合処理の複製にあった。この整理と、元から未登録だったAIサービスについては [未使用コードの整理](legacy-code.md) を参照。稼働する連合処理を削除して診断を消したものではない。

## 分けて扱った既存の不具合

ユーザーの承認に基づき、以下は型定義だけの変更とは別コミットで修正する。

- 固定ユーザー一覧の誤記を直し、削除済みアカウントを除外する。
- ファイルアップロードの `meta` 変数名の衝突を直し、既定のエラーコードを返す。名前検証やメタデータ取得が失敗した場合も一時ファイルを削除する。
- ローカルのCreate/Likeを生成するとき、Promiseのままデータを包まず描画を待つ。絵文字の更新日時も関数ではなく文字列として出力する。
- 失われたOpenAPI生成関数を履歴の上流実装から復元する。パラメーター定義を変更しない純粋な変換を使い、APIトークンを実際の仕様どおりリクエスト本文に記載する。
- `admin/meta` の宣言を、実際に返している項目・null許容・SMTPポートの数値型に合わせる。返り値を型に合わせて作り変えない。
- CAPTCHAは `node-fetch` の通信オプションを使い、外部JSONを検証する。登録API・URLプレビュー・inboxも、外部入力を型アサーションで信用せず検証する。未定義の翻訳キーが文字列以外を返すケースも処理する。
- `node-fetch` 3で無効なtimeoutオプションを外し、AbortSignalを使う。実際の中断時間は従来の `timeout × 6` を維持する（既定値なら60秒）。既存の待ち時間を短くして連合取得を失敗させないこともHTTP fixtureで確認する。

入力検証の追加により、型契約を満たさないデータは処理に渡さない。正常なMastodon形式の投稿、通報のURI配列、コレクション、拡張フィールドの保持をテストした。外部の実サーバーとの連合、実SMTP/OAuth/S3、および本番の全データでの互換性を保証するものではない。

## 再発を防ぐ検証

```sh
yarn typecheck:backend
NODE_ENV=production yarn build
yarn jest
node --test scripts/test/normalize-yarn-aliases.test.mjs
```

`typecheck:backend` は全productionバックエンドソースと型契約テストを検査する。型契約テストには誤った受信者ID、必須条件の欠落、不正な連携情報などを拒否する確認を含む。今回の回帰テスト自身も型検査の対象にしている。

バックエンドbuildの `tsc ... || echo done` を削除し、`noEmitOnError` を有効化した。型エラーがあればビルドと保守ブランチのCIを失敗させる。型検査の成功をJSの出力だけで判定しない。

82件のJestテスト、型契約のコンパイル、クリーンな本番ビルド、実アプリのHTTP smokeを確認する。smokeには `/api.json` も追加した。DB確認は小さなローカルfixtureのみで行い、本番DBをコピーしない。

ローカルDBの97テーブルのスキーマは前段の保存結果と一致し、保守ブランチに新しいマイグレーションはない。保存データの比較では、アプリの起動に伴う連合統計テーブルへの3行追加を分けて確認する。その他96テーブルと、統計テーブルの元の11行のハッシュは一致する。本番データに対する検証結果ではない。

## 残る範囲

今回の0件は、以前から報告していたバックエンド301件に対する結果である。既存コードのすべての `any` を撤去したという意味ではない。レスポンススキーマがないAPIの結果も、現段階では `unknown` として扱う。

上記のバックエンド修正時点ではクライアントと SW の厳密な検査は未完了だった。その後の全 Vue SFC・テンプレート・SW の厳密な型検査と依存更新は [フロントエンド保守の記録](frontend-maintenance-2026-10-24.md) を参照。

依存・Misskey本体の既知脆弱性の解消状況は [依存更新の記録](dependency-updates.md) とアドバイザリー一覧で引き続き管理する。型検査0件は安全性の完了判定ではない。
